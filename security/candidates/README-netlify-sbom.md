# Périmètre SBOM — candidat 26 novembre 2026
Le workflow génère CycloneDX avec npm en mode lockfile-only, offline, sans installation, sans lifecycle scripts, sans secrets ni droits de déploiement. Le lock Netlify existant est vérifié par le contrat de SHA-256 approuvé. Le reçu lie SHA source, SHA du lock, SHA du SBOM et version npm, sans prétendre constituer une signature.
Le contrôle compare les chemins, noms, versions, empreintes SHA-512 et références du graphe. Tout paquet obligatoire manquant ou inconnu est refusé ; les omissions optionnelles sont explicitement listées et empêchent de revendiquer une couverture complète. L'audit npm existant reste distinct.
Périmètre réel relevé : 1015 entrées Netlify, 923 couples nom/version, 80 entrées optionnelles. Le manifest mobile est présent mais les quatre chemins usuels package-lock.json, npm-shrinkwrap.json, yarn.lock et pnpm-lock.yaml ne sont pas trouvés à ce SHA. Ne pas prétendre disposer d'un SBOM exhaustif du mobile, des imports Edge, scripts navigateur, GitHub Actions ou de la plateforme hébergée. Priorités : lock mobile revu, inventaire des imports runtime, audit des licences et vulnérabilités, signature de provenance du SBOM après validation. Aucun déploiement et aucune publication dans l'artefact web.
